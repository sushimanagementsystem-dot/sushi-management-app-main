# CONVENTIONS.md

Confirmed from actual config/code — not framework defaults assumed.

## `nest-backend/`

- **Pure ESM.** `package.json` has `"type": "module"`; `tsconfig.json` uses
  `"module": "nodenext"` / `"moduleResolution": "nodenext"`. Relative imports include the `.js`
  extension even in `.ts` source (e.g. `import { AppModule } from './app.module.js'` in
  `main.ts`) — this is required by `nodenext` resolution, not a typo; keep it when adding files.
- **Strict TypeScript** (`"strict": true"`), decorators enabled
  (`experimentalDecorators`/`emitDecoratorMetadata`, needed for Nest's DI).
- **Prisma fields are `snake_case`**, not Prisma's usual camelCase — deliberate 1:1 port from the
  Google Sheet (see `DATABASE.md`). Don't "fix" field names to camelCase.
- **Enum-like DB columns are plain `String`, not Prisma enums** — most are backed by the runtime-
  editable `enum_option` table. Don't convert one to a compile-time enum without checking
  `field_schema.enum_source` for that column first.
- **Comments explain WHY, not WHAT** — the codebase consistently uses comments to record a
  non-obvious constraint or the reason behind a specific number/choice (e.g. `main.ts`'s 25mb
  body-limit comment citing a real failed submission; `secrets.service.ts`'s key-derivation
  rationale). Follow this pattern rather than adding describe-what-the-code-does comments.
- **Lint/format**: `oxlint.json` (oxlint config) + `.prettierrc`. Run via `npm run lint` /
  `npm run format`.
- Tests colocated with source as `*.spec.ts` (vitest), not in a separate `__tests__/` tree.

## `frontend-next/`

- Auth *state* lives in Zustand (`lib/store/useAuthStore.js`); components that re-render on auth
  changes use the hook, imperative call sites (mount-effect redirects) use the plain functions in
  `lib/api.js` instead — this split is intentional, not redundant (see `ARCHITECTURE.md`).
- Data fetching goes through TanStack Query (`lib/queries.js`), not ad-hoc `fetch`/`useEffect`.
- Kiosk identity is a URL artifact, read from the dynamic `[slug]` segment — never trust a slug
  as an authority; the kiosk `token` (from the `?token=` link, persisted per-slug) is the real
  credential. New top-level routes must be added to `proxy.js`'s `RESERVED_SEGMENTS` or they'll
  be swallowed by the `[slug]` catch-all.
- No test framework configured — don't add one without the user asking (see `TESTING.md`).
